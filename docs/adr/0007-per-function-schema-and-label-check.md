# ADR 0007: Per-function router schema and a post-routing label check

- **Status:** Accepted
- **Date:** 2026-10-08
- **Resolves:** the open regressions in
  [ADR 0006](0006-label-vocabulary-in-schema.md)

## Context

Moving the label vocabulary into the schema (ADR 0006) caused two regressions:

1. **`recent` lost `n`.** The schema had one shared `args` object with every
   argument optional, so when the prompt grew by 80 labels, nothing stopped
   the model leaving `n` out ("what was the last thing you saw?" → 5 visits).
2. **The guard missed "people and dogs".** Its multi-label check recognized
   "people" through the removed synonym table.

## Decision

**A. Per-function schema.** `ROUTER_SCHEMA` is an `anyOf` with one branch per
entry in `ALLOWED_ARGS`, generated by `_function_schema()`. Each branch fixes
`function` to one name (`const`) and lists exactly that function's args, all
required. Optional args are still nullable; `REQUIRED_ARGS` makes them
non-null. It's still one model call; only the schema says which args belong to
which function. Missing or extra args can no longer be produced.

**B. Post-routing label check.** `route()` reads as: guard the question, then
`_ask_model()`, then guard the answer. If the routed call has a label and the
question *literally* names a different detector label (`labels_mentioned()`),
the call becomes `unclear`. Answering for one object when two were asked for
silently drops the other.

Rejected:
- `REQUIRED_ARGS` + retry for `n`: costs a model call each time and only
  treats the symptom.
- Removing the label list from the prompt: likely to hurt word mapping.
- Having the model list every mentioned label: probabilistic, and a bigger
  schema.
- A small irregular-plural table ("people" → person): brings back the
  hand-written coupling ADR 0006 removed.
- **C. A prompt example for categories** ("appliances" → not_a_detector_label):
  measured. It didn't fix "vehicles" → truck, and it broke "automobiles" →
  car (now truck). It was dropped to avoid prompt tuning for an edge case.

## Results (gemma2:2b, guard on, laptop; sets grown before any run)

| Variant | Tuning (52) | Held-out (45) | Words mapped | Declines (held-out) | To chat | Retries (held-out) |
|---|---|---|---|---|---|---|
| ADR 0006 (before) | 43 (83%) | 35 (78%) | 11/11 | 7/12 | 0 | 2 |
| A only | 46 (88%) | 36 (80%) | 11/11 | 7/12 | 0 | 0 |
| B only | 44 (85%) | 37 (82%) | 11/11 | 9/12 | 0 | 2 |
| **A + B (chosen)** | 46–47 (88–90%) | **38 (84%)** | **11/11** | **9/12** | **0** | **0** |
| A + B + C | 47 (90%) | 39 (87%) | 10/11 | 10/12 | 0 | 0 |

Repeat runs at temperature 0 differ by about ±1 question. The schema is ~3x
larger (1.3k → 3.8k characters) with no measurable latency change on the
laptop.

## Known limits

- **Both sides synonyms** ("pups or kittens") → `count(cat)`: B only sees
  literal label words.
- **Categories** ("pets", "electronics", "vehicles") are sometimes forced onto
  one label instead of `not_a_detector_label`. The real fix is a feature
  (counting several labels for a category), not more prompt tuning.
- **Chat-feature gate:** held-out is 84%, below the 90% gate from ADR 0005.
  The held-out set grew from 30 to 45 with deliberately hard questions, so this
  isn't like-for-like with ADR 0005's 90% (on 30). Whether to keep the gate as
  is, or to re-baseline it on the larger set, is an open decision.
